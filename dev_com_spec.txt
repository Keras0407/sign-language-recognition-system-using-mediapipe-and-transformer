1. PURPOSE OF THIS DOCUMENT
--------------------------------------------------------------------------------

This specification records the exact computer that is used to:

  (1) run MediaPipe hand / face / lip landmark extraction,
  (2) preprocess sign-language video into landmark sequences,
  (3) train and evaluate recognition models (typically PyTorch / TensorFlow),
  (4) write reproducible experimental settings for the paper.

It also states software, GPU, and library requirements that must stay
compatible with this machine. Later chat turns and later code must treat these
values as fixed constraints.

3.2 MediaPipe (feature extraction / theoretical front-end)
  Role in system:
    MediaPipe is the perception front-end. It converts each RGB video frame
    into a compact, semantically meaningful landmark graph:
      - 21 3D hand keypoints per hand (Hands / Hand Landmarker)
      - 468 (or 478 with iris refine) 3D face keypoints (Face Mesh)
      - lip / mouth contour subset (FACEMESH_LIPS) for mouthing / visemes
      - optional 33 pose keypoints + both hands + face (Holistic, 543 pts)

  Recommended Python packages (pin in the project venv):
    - mediapipe          (Python 3.10 wheel)
    - opencv-python      (video I/O, BGR<->RGB, visualization)
    - numpy
    - protobuf           (version required by the chosen mediapipe wheel)

  Two API generations exist in the local mediapipe/ tree:
    A. Legacy Solutions API
         mp.solutions.hands.Hands
         mp.solutions.face_mesh.FaceMesh
         mp.solutions.holistic.Holistic
       Still the most common API in sign-language papers and tutorials.
    B. Tasks API (current)
         mediapipe.tasks.python.vision.HandLandmarker
         mediapipe.tasks.python.vision.FaceLandmarker
         mediapipe.tasks.python.vision.HolisticLandmarker
       Preferred for new code. Same landmark topology, newer graph.

  Important runtime fact for THIS machine:
    MediaPipe landmark inference on Windows Python is typically CPU/XNNPACK
    (and optionally GPU via OpenGL), NOT via the CUDA 12.9 / cuDNN 9.12
    stack. That CUDA stack is reserved for the recognition-network training
    stage. Do not write the paper as if MediaPipe Hands "runs on CUDA 12.9".
    Write: landmark extraction with MediaPipe; classifier training on
    RTX 5060 Laptop (CUDA 12.9, cuDNN 9.12).

3.3 Deep-learning training stack (must use the GPU profile)
  Intended use:
    Sequence models over MediaPipe landmarks (e.g. transformer, BiLSTM,
    TCN, graph convolution, or hybrid CNN+RNN on landmark heatmaps /
    coordinate streams).

  Requirements:
    - Framework with official or vendor CUDA 12.x Windows wheels
    - cuDNN 9.12 compatible build
    - Batch size and sequence length must respect ~8 GB laptop VRAM
    - Mixed precision (FP16 / TF32) recommended on RTX 50-series
    - num_workers for DataLoader should stay modest on Windows
      (start with 0 or 2; Windows spawn is not Linux fork)

  VRAM planning on RTX 5060 Laptop (treat 8 GB as the cap):
    Landmark-only sequence models     : comfortable (batch 32–128 typical)
    RGB video backbone (ResNet/ViT)   : tight; use small batch, AMP, freeze
    Holistic 543-D x T sequences      : comfortable if not also decoding
                                        many HD videos on GPU
    Simultaneous extract + train      : avoid; extract landmarks offline
                                        first, then train on .npy/.pt cache

3.4 Video and dataset tooling

4. FUNCTIONAL REQUIREMENTS OF THE SLR PIPELINE ON THIS MACHINE
--------------------------------------------------------------------------------

4.1 Must-have perception modules (MediaPipe)
  R1. Two-hand landmark extraction
      21 keypoints x 2 hands, with handedness (Left / Right).
      Use Hands or HandLandmarker. max_num_hands = 2.

  R2. Lip / mouth landmark extraction
      Face Mesh / Face Landmarker with refine_landmarks = True
      (Attention Mesh) so lip and iris regions are higher accuracy.
      Downstream code must slice FACEMESH_LIPS (outer + inner mouth
      contours), not the full 468-point mesh, unless ablation needs all
      face points.

  R3. Optional but recommended: Holistic
      33 pose + 468 face + 21 + 21 hands = 543 landmarks, semantically
      consistent left/right assignment. Best when signs use body shift,
      shoulder, or non-manuals together with hands and mouth.

  R4. Temporal tracking mode for video
      static_image_mode = False (legacy) or VIDEO / LIVE_STREAM running
      mode (Tasks API). Detector runs on the first frames and on tracking
      loss; landmark model tracks in between. This is required for
      real-time and for long sign videos.

4.2 Must-have training / evaluation behaviour
  R5. Offline landmark cache
      Because the laptop GPU is shared and MediaPipe is CPU-heavy,
      extract landmarks once per video, save them, then train on tensors.

  R6. CUDA training only on the classifier
      Landmark files are small. The RTX 5060 Laptop + CUDA 12.9 +
      cuDNN 9.12 is used to train/evaluate the sequence model.

  R7. Reproducibility
      Record: Python 3.10, mediapipe version, OpenCV version, torch/tf
      version, CUDA 12.9, cuDNN 9.12, GPU name, Windows 10 64-bit,
      random seed, FPS, detection/tracking confidence thresholds.

4.3 Quality thresholds (defaults; tune on the dataset)
  min_detection_confidence : 0.5
  min_tracking_confidence  : 0.5
  refine_face_landmarks    : True   (required for lip-focused SLR)
  model_complexity (hands) : 1      (full) unless latency forces 0
  model_complexity (pose)  : 1      (Holistic default)

4.4 Known constraints on this laptop
  C1. Laptop TGP: long training jobs will thermal-throttle. Prefer
      overnight landmark extraction on CPU, then GPU training with AMP.
  C2. 8 GB-class VRAM: do not plan large RGB video backbones without
      gradient checkpointing / frame sampling.
  C3. Windows file locking and DataLoader spawn: keep workers low.
  C4. Handedness assumes a mirrored selfie image. For unmirrored dataset
      videos, swap Left/Right in post-process.
  C5. MediaPipe Hands is trained for visible palms/fists; heavy motion
      blur, gloves, or extreme out-of-plane rotation will drop track.
      The paper should state this as a limitation of the front-end.


--------------------------------------------------------------------------------
5. WHY THIS STACK MATCHES THE PAPER
--------------------------------------------------------------------------------

Sign language is multi-articulatory: manual features (handshape, orientation,
movement, location) plus non-manual features (mouthing, lip aperture, cheek,
jaw, eyebrows). MediaPipe is the correct theoretical and practical front-end
because it already decomposes a monocular RGB frame into those articulators
as 3D landmarks, at real-time speed, without a depth camera.

This computer is sufficient for that design:

  - MediaPipe landmark graphs are light enough for Python 3.10 on Win10
    even when the GPU is busy.
  - The RTX 5060 Laptop with CUDA 12.9 and cuDNN 9.12 is enough to train
    a landmark-sequence recognizer (the usual SLR research setup).
  - Full end-to-end RGB video transformers may not fit comfortably in
    laptop VRAM; the paper's main path should be MediaPipe landmarks ->
    sequence model, with RGB baselines only if memory allows.

Do not change OS, Python, CUDA, or cuDNN in later requirements without
updating this file first.

8.4 Why cu128 and not a "cu129" wheel
  Official PyTorch Windows Blackwell builds are published as cu128
  (and newer cu13x). There is no separate cu129 torch wheel that we
  must match to the system toolkit. CUDA 12.9 on the laptop is the
  driver/toolkit. The 2.11.0+cu128 wheel contains sm_120 kernels.
  That is the combination that actually runs on RTX 5060.

8.5 Offline SLR pipeline (how the libraries are used)
  Stage 1  Decode stored sign videos (OpenCV / PyAV / imageio-ffmpeg).
  Stage 2  MediaPipe Hands + Face Mesh (refine_landmarks=True) or
           Holistic. Write landmark sequences to .npy / .pt on disk.
  Stage 3  Train the recognizer with PyTorch 2.11.0+cu128 on the 5060.
           Use AMP. Keep DataLoader workers at 0 or 2 on Windows.
  Stage 4  Evaluate from the same cached landmarks. No live camera
           required for the paper experiments.
